# 视觉财税报告设计原则

> 基于用户两次纠正沉淀的设计模式。第一次：内容太浅只有一句话（"财税上体现不出风险和紧迫"）。第二次：文字太多图太少（"图反而没有"）。最终平衡点：以图为主，字为辅助。

## 黄金法则

**图为主，字为辅**。每个风险页的核心是视觉冲击——图表、示意图、icon化的关键数字。文字压缩到最低限度：标题 + 关键数字 + 一句话结论。

## 标准页面结构

```
┌──────────────────────────────────────────┐
│ 🏦 风险名称          风险等级    页码    │ ← 顶部：标题+tag+页码
├──────────────────────────────────────────┤
│  53        105万        52%              │ ← 巨型关键数字（视觉主力）
│  过桥资金   现金取现    摘要模糊          │
├──────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────┐     │
│  │  SVG图表区   │  │  SVG图表区   │     │ ← 图占视觉主导
│  │  资金流向图  │  │  法规后果图  │     │
│  └──────────────┘  └──────────────┘     │
├──────────────────────────────────────────┤
│ 💬 一句大白话总结                         │ ← 底部：人话收尾
└──────────────────────────────────────────┘
```

## 设计演变（这个教训很重要）

| 版本 | 用户反馈 | 问题 |
|:----|:--------|:-----|
| V1：卡片网格（7卡排列） | "一句大白话体现不出财税紧迫" | 内容太浅 |
| V2：翻页+双栏详细分析 | "太多字了，图反而没有" | 文字太多，变成了普通报告换皮肤 |
| V3（最终版）：翻页+图为主 | ✅ 通过 | 每页一个大型SVG图+3个关键数字+一句话 |

## 每页内容模板

### 封面
- 大标题 + 副标题
- 2-3个核心统计数字
- 资料说明
- "开始"按钮

### 企业概况
- 4个巨型关键数字
- 风险全景SVG矩阵（7个风险方块）
- 一句话判断

### 每个风险页（共7页）
- **顶部**：图标 + 风险名称 + 风险等级标签（高/中/低）+ 页码
- **中部**：3个巨型关键数字（42px，色块背景）
- **主体**：1-2个大型SVG图表（资金流向图/对比图/饼图/柱状图/流程图等）
  - SVG必须用 viewBox 自适应
  - 颜色语义：红=极高/高，橙=中，蓝=信息，绿=正面
- **底部**：一条大白话总结（渐变背景条）

### 总结页
- 3个优先级数字
- 双栏行动建议
- 一句话建议
- 需要的补充资料

## 图表类型选择

| 场景 | 用什么图 |
|:----|:--------|
| 资金流向 | 流向图（矩形+箭头+虚线回流） |
| 数据对比 | 柱状图/对比条 |
| 占比 | 堆叠条形图 |
| 关系 | 流程图/链路图 |
| 账务变化 | 柱状对比（年初→年末） |
| 风险等级 | 色块矩阵/标签 |
| 商业合理性 | 对比卡片（车价 vs 利润） |
| 客户集中度 | 饼图/占比图 |
| 风险拆分 | 并列税务后果卡片 |

## 代码实现要点

```html
<div class="flip-book">
  <div class="page active" data-page="0">...</div>
  <div class="page" data-page="1">...</div>
</div>
<div class="nav-bar">
  <button class="nav-btn">‹</button>
  <div class="dots"></div>
  <button class="nav-btn">›</button>
</div>
<script>
// 翻页控制：opacity + translateX 切换
// active=当前页, prev=左侧堆叠
function goTo(n) {
  pages.forEach((p,i)=>{
    p.classList.toggle('active',i===n);
    p.classList.toggle('prev',i<n);
  });
}
</script>
```

CSS 关键：`.page.active { opacity:1; transform:translateX(0); z-index:2 }`
`.page.prev { opacity:0; transform:translateX(-50px); z-index:1 }`

## 案例脱敏标准流程

把真实报告放到网站/作品集前，必须脱敏：

### 必须替换的
| 信息类型 | 替换方式 | 例子 |
|---------|---------|------|
| 公司名 | 行业代替 | "和胜耐火" → "某耐火材料企业" |
| 人名 | 角色代替 | "樊晓东" → "控股股东（持股X%）" |
| 地址 | 模糊化 | "振兴大道149号" → "某产业园区" |
| 个体户名 | 字母代替 | "潢川县瑞扬劳务服务部" → "个体户A" |

### 保留的
金额、比例、法规依据、分析逻辑、风险等级——全不动，脱了报告就没价值。

### 操作方式
```python
replacements = {
    '郑州和胜耐火材料有限公司': '某耐火材料贸易企业',
    '樊晓东': '控股股东（持股X%）',
    '潢川县振兴大道149号': '某产业园区',
}
for old, new in replacements.items():
    content = content.replace(old, new)
```

## Vitepress 网站部署注意

把 HTML 案例报告放入 Vitepress 的 `public/reports/` 目录，构建后自动部署到 `/reports/` 路径下。

### SPA 冲突修复
Vitepress 的 SPA 路由会劫持页面加载，导致自定义 HTML 的 body 被清空。在报告 HTML 的 `<head>` 第一行加：
```html
<script>if(window.location !== window.parent.location || document.querySelector('.VPNav')) location.reload()</script>
```
这行脚本检测到被 Vitepress SPA 包裹时强制硬刷新，绕过路由。

### 链接写法
```markdown
<a href="/reports/naicai-report" target="_blank">打开翻页报告 →</a>
```
用 `target="_blank"` 新标签页打开 + 不带 `.html` 后缀（`cleanUrls: true` 时）。

### 行号污染修复
用 `read_file()` 修改 HTML 文件后，内容可能被写入行号前缀 `1|` `2|` `3|`。修复方法：
```python
import re
content = open('file.html').read()
fixed = re.sub(r'^\d+\|', '', content, flags=re.MULTILINE)
open('file.html', 'w').write(fixed)
```
